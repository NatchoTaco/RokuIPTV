# StreamForge API Contract

All API endpoints use the `/api/v1` prefix. The OpenAPI schema is generated by the FastAPI application and stored in `packages/api-contract/openapi.json` when exported.

## Milestone 1 Endpoints

### Health

- `GET /api/v1/health`
- `GET /api/v1/readiness`

Health reports service status, version, database reachability, Redis reachability, and setup completion state.

### Authentication

- `POST /api/v1/auth/bootstrap-admin`
- `POST /api/v1/auth/sign-in`
- `POST /api/v1/auth/sign-out`
- `GET /api/v1/auth/me`

Bootstrap administrator creation is allowed only before setup is complete and only when no administrator exists.

### Setup

- `GET /api/v1/setup/state`
- `PATCH /api/v1/setup/state`

Setup state persists first-run wizard progress and installation mode. Milestone 1 supports account and installation-mode steps.

### Settings and Diagnostics

- `GET /api/v1/settings/public`
- `GET /api/v1/diagnostics/summary`

Milestone 1 exposes only non-sensitive settings and diagnostic status.

## Future Endpoint Areas

The specification reserves these `/api/v1` areas for later milestones:

- `/sources`
- `/playlists`
- `/epg-sources`
- `/channels`
- `/channel-groups`
- `/cleanup`
- `/guide`
- `/recordings`
- `/recording-rules`
- `/devices`
- `/pairing`
- `/profiles`
- `/favorites`
- `/playback`
- `/storage`

Deferred endpoints must not return fake successful behavior. They should be absent or clearly marked as not implemented until their milestone begins.

## Dashboard Contract Strategy

The dashboard uses typed fetch helpers and Zod schemas for runtime validation. Generated types from OpenAPI can replace or supplement these helpers after the schema export workflow is stable.
